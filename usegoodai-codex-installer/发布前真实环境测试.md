# 在 GitHub Actions 测试发布成品的真实使用流程

流程版本：1.0.1。首次制定：2026-11-09。更新日期：2026-11-10。

本文供修改、打包和发布工具的工作者执行。发布前使用 GitHub 托管的 macOS、Windows 运行器，尽可能复现用户下载、打开工具、导入配置、重新打开 Codex 和执行任务的过程；不要求用户提供专用机器或真实 API Key。

这是测试流程说明。本次不新增必需检查、分支保护或发布阻断逻辑，也不改变已有门禁配置。本文列出的桌面用例是待补充和执行的测试要求，不能因文档已写入就记为测试通过。

## 使用假 Key 和本地模拟接口

- 每次运行生成仅供测试的假 Key，使用独立的临时 `CODEX_HOME`、工作目录及必要的应用用户数据目录。不读取工作者或用户的真实凭据和历史任务。
- 在运行器本机启动模拟服务，按实际客户端协议返回密钥检查、模型列表、流式响应和工具调用结果。模型与生图请求均只发往本地模拟服务；不索要真实 Key，不把真实 Key 放进聊天、仓库、GitHub Secrets、日志或附件。
- 为模拟测试设置的接口覆盖必须单独记录，并与成品原本写入的正式地址分别核对。不得修改候选成品内部代码来绕过失败，再宣称原成品通过。
- 假接口通过只证明客户端和工具的交互流程。真实中转站鉴权、计费、外网上游连通性和模型输出质量均标为「未验证」，不得写成真实接口已通过。
- 联网下载官方软件与使用真实模型 Key 是两件事。安装软件后，可限制模型请求的外部网络访问，验证只连接中转站的使用场景；不要切断运行器与 GitHub 的控制连接。

## 在 Actions 准备候选成品和官方 App

1. 检出本次待发布提交，读取对应候选 ZIP 和安装脚本，记录提交哈希、各工具版本、ZIP 哈希。测试后重新打包或替换文件，受影响的用例需重跑。
2. 使用 GitHub 托管的 Apple 芯片 macOS 和 Windows 环境，记录实际系统版本、CPU 架构、用户权限、Shell 版本及运行器镜像版本。Windows Server 和 Windows 11 ARM 的结果不得写成 Windows 11 x64 原生桌面已验证。
3. 安装真实官方 ChatGPT/Codex App，记录 App 版本、安装位置和内置后端版本。修改涉及兼容性时，分别测试上一稳定安装状态和当前官方版本，覆盖 App 更新后内置后端位置变化。
4. 从候选 ZIP 解压成品，保留可执行权限。Mac 从 `.app` 启动，Windows 从交付 `.exe` 启动；涉及网站导入时通过系统打开 `usegoodai://` 链接。只运行内部脚本不能算双击入口测试。
5. 先验证运行器桌面能截图、能定位和操作控件，确认窗口属于实际被测 App。桌面、权限或控件不可用时保留证据并标记「未验证」或「失败」，不得跳过后记为成功。

## 按用户顺序操作并实际打开 Codex

1. 首次打开接入助手，用假 Key 连接本地模拟服务。分别覆盖粘贴输入、剪贴板和网站链接入口中本次改动涉及的路径，检查提示、配置、备份及进程关闭结果。
2. 按交付说明安装生图工具，再导入国产模型。Windows 使用合并助手内的入口；Mac 按工具 1、2、3 的顺序运行。检查先前安装的工具与无关配置仍可用。
3. 通过系统应用入口重新打开真实 Codex 主窗口，等待可操作状态，检查配置错误、首次设置卡住、白屏、闪退和反复要求配置等问题。后台进程存在、`--version` 成功或模型目录可解析均不能替代此步。
4. 在 Codex 界面打开模型选择器，检查导入模型和应保留的官方模型，选择本次被测模型。核对原默认模型、接口和假 Key 的保留或预期更新结果。
5. 在临时项目中新建任务，由界面提交测试指令。让本地模拟服务返回确定的工具调用，驱动真实 Codex 创建指定内容的文件；同时检查界面任务完成、模拟服务收到的模型及请求格式、真实文件结果。不要只检查回复文字。
6. 生图安装或 Skill 有改动时，让模拟响应驱动 Codex 实际调用交付的生图程序，核对调用参数和测试输出文件；模拟图片输出不能作为真实模型生图质量的验证。
7. 退出后再次打开 Codex，新建任务复查配置和模型选择是否保留。助手重开后检查已安装、已导入或需重新导入等状态是否符合实际。

## 尽可能复现用户实机会遇到的问题

根据本次改动选择相关用例，先重现已报告故障，再验证修复；不把所有检查都停留在源码和理想初始状态。

| 场景 | 在 Actions 中执行并核对的动作 |
| --- | --- |
| Mac 原生环境 | 使用系统 `/bin/sh`、`/bin/bash` 和 JXA；不依赖预装的新版 Bash、Node 或 Homebrew 掩盖运行依赖；检查 Bash 3.2、中文语言环境和 `.app` 可执行权限。 |
| Windows 原生环境 | 涉及安装脚本时覆盖系统 PowerShell 5.1；涉及窗口时操作真实交付 EXE，记录 WebView2、用户权限、系统提示和窗口行为。 |
| 后端定位 | 分别测试实际官方 App 的内置 CLI、包装入口和相关安装位置；覆盖 PATH 没有 Codex、用户目录含中文或空格，以及 `.codex` 已有生图工具但仍需找到真正后端的状态。 |
| 旧配置与升级 | 使用临时旧版配置、已安装生图工具、自定义模型和无关设置；执行升级、重复导入、恢复及卸载，逐项核对保留范围。 |
| Codex 正在运行 | 先打开真实 Codex，再执行接入或模型导入；检查应关闭的 App 是否实际退出，随后重新打开并新建任务。 |
| 多窗口与重复操作 | 覆盖助手已打开时再次打开、快速重复点击、链接唤起、窗口接管和退出后重开，检查重复写入、忙碌状态和窗口消失。 |
| 系统首次授权 | 尽可能保留并操作终端控制授权、下载来源提示及安装配置提示；记录是否预授权、提权或移除了下载标记。预先绕过的步骤不能算首次授权测试通过。 |
| 网络和接口失败 | 用模拟服务返回无效 Key、401/403、429、500、非 JSON、超时和流中断；对照该工具约定核对提示、文件是否被误写、任务能否恢复。 |
| 下载和管道执行 | 测试本次发布脚本的 HTTP 下载与管道入口，记录下载端和执行端各自退出码；覆盖下载中断、截断文件，检查 `curl` 写入失败之前的实际脚本错误。 |
| 文件和权限失败 | 在临时目录模拟不可写文件、占用或无效配置；检查错误提示、备份、回滚和原文件保留，不在失败后留下半份配置。 |

需要普通用户权限才能复现的问题，应增加可用的受限用户用例。不能因运行器默认具有较高权限，就宣称客户普通账户也已验证。托管环境无法复现的系统安全桌面、安装来源提示或机器特性，明确记录限制，不要求用户另备专用机器，也不关闭安全机制来把失败改成通过。

## 从现有测试入口继续补齐

先检查当前分支中工作流与脚本的实际内容，再执行本次相关的测试。已经停用或只做取消操作的诊断工作流不能作为测试成功证据。

| 现有入口 | 已有覆盖及仍需补齐的范围 |
| --- | --- |
| [mac-quick-connect.yml](../.github/workflows/mac-quick-connect.yml) | Mac 系统 Shell、助手构建和部分链接启动测试；不能据此认定 Codex 主窗口、新任务或完整终端授权已验证。 |
| [windows-quick-connect.yml](../.github/workflows/windows-quick-connect.yml) | Windows 原生回归、助手窗口及接管测试；助手窗口测试不能替代真实 Codex 桌面任务。 |
| [tools-release-check.yml](../.github/workflows/tools-release-check.yml) 中的 Mac 测试 | 安装官方 App 后调用内置后端、执行导入和交付 App 内的脚本；当前没有通过 Codex 主窗口发起任务。其既有门禁属性不扩展到本文新增测试。 |
| 历史分支 `image-rules-self-check` 的 `windows-image-tool.yml` 与 `tests/windows/mock_responses.py` | 已有真实 Codex 后端配合本地模拟响应的测试，尚未进入主线；复用前先提取、审查并提交相应测试文件。不能记为 Codex 桌面界面测试。 |
| [fake_usage_server.py](tests/fake_usage_server.py) | 已有假 Key 和本地密钥检查响应，可复用异常场景；单独通过不代表客户端真实接口连通。 |

新增桌面测试使用独立的 Actions 测试工作流，按改动范围执行并上传测试报告；不加入必需检查列表，不接入发布阻断脚本。不要为了本流程重新配置分支保护或索要管理权限。

## 如实提交测试记录

每次记录以下内容：

- 候选提交、流程版本、工具版本、ZIP 哈希、Actions 运行链接与附件名称。
- 实际系统与架构、官方 App 和后端版本、Shell、用户权限及预授权情况。
- 每个用例的「通过 / 失败 / 未验证」、实际操作、预期和实际结果；未验证项写明具体原因，不能只写工作流整体绿色。
- 关键步骤截图、必要的界面控件信息、退出码、相关日志、模拟请求记录及任务生成文件；仅上传经过选择的测试证据，不上传完整用户目录或含凭据的配置。
- 区分「脚本通过」「后端通过」「Codex 桌面任务通过」和「真实中转请求未验证」。修复失败后重跑受影响用例，保留修复前后的证据。
