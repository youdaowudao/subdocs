## 独立审查发现的回归修复

1. 合法的转义 Windows 路径被再次解释为 Unicode/控制字符：改为逐个反斜杠 token 解码，以 TOML 标准解析器作对照。
2. 完整配置复制到暂存目录后，相对指令文件失效：暂存使用最小配置校验模型目录，提交后在原配置目录校验实际加载；失败仍恢复文件，成功后才关闭客户端。
3. 只比较 ID 会把同 ID 的旧元数据视为成功：比较暂存与实际原生导出的完整模型对象，新增错误元数据的恢复测试。
4. JXA 的 bridged nil 使用 `.isNil()` 判断，依据 Apple 官方桥接说明修正；其真实运行仍列入下方实机验收。

## 泛化错误提示修复与本机配置副本实测

用户报告 Linux 只显示“文件格式或系统操作失败”，没有文件或步骤信息。这一缺陷已修复：共享核心在读取配置、解析已有模型/管理记录、导出内置目录、合并、暂存、备份、提交和实际校验各步骤保留上下文；Shell 入口显示步骤、文件或命令、原因、系统错误码与后端退出码。损坏元数据指出 `models[n]` 和具体字段。

新增 7 项回归测试覆盖损坏/空的模型 JSON、无效 UTF-8、ENOTDIR、真实 EACCES、后端输出不是 JSON、带配置片段的后端错误、内部 TypeError。确认输出含定位信息，配置不变，测试哨兵凭据不出现在错误文本中。JSON 仅提取数字位置；后端 stderr 只提取受控原因和已知字段名，不原样输出异常或配置片段。

按用户明确授权，用完整本机 `.codex` 创建私有隔离副本。自动重定位副本中的原目录路径，凭据文件直接复制，不查看或输出其内容。分别使用实际 Codex 二进制与官方 npm 启动器执行生成的完整管道安装脚本，两次都成功导入 8 项；原始配置与认证文件前后校验一致，进程终止被拦截。副本和私有测试输出只留在忽略的 `tests/.work/`，不提交或发布。

独立代理还验证了官方 npm 启动器配合原 GPT 安装器同结构配置的完整管道导入。当前确定修复的是“错误上下文被吞掉”；这些成功实测没有复现用户当次失败，不能把故障注入中的坏 JSON 当作用户的实际根因，仍需新版输出确认。
