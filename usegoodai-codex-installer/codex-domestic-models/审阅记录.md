## 第二位代理的具体结论与修订

| 讨论点 | 结论与已做修订 |
| --- | --- |
| 正常升级是否要求重跑 | 官方方法在用户配置目录持久化，没有每次升级自动执行步骤；不把升级视为必然失败，不设计自动重跑 |
| 只改目录路径是否完整 | 不完整：官方同时配置并校验桌面推理档位；已补入必要的 `[desktop].enabled-reasoning-efforts` 合并，保留原 GPT 档位及其他设置 |
| GPT 从哪里保留 | 原有有效目录优先保留完整对象；App 对应目录只补缺，不能只取内置目录覆盖原有模型 |
| 保留对象与更新是否冲突 | GPT 和用户其他模型保留；本工具国产条目重跑时整条替换，避免过时字段残留 |
| 如何识别取消的旧模型 | 只记录上次管理的 `slug` 列表，GPT 不纳入，不建立额外管理系统 |

证据：[DeepSeek 官方方法](https://api-docs.deepseek.com/zh-cn/quick_start/agent_integrations/codex/)及 [官方 Shell 脚本](https://cdn.deepseek.com/api-docs/codex-deepseek-setup-en.sh)。主代理另外复核了脚本的桌面配置常量。

第二位代理已回看修订稿，补充明确了档位合并规则：已有字段和没有字段两种情况都要加入国产模型所需档位，不能把已有字段理解为跳过更新。该表述已修正，其余没有实质性问题。文档内部链接、名单一致性和行尾空白检查通过；这不代表尚未实施的脚本已通过功能验证。
