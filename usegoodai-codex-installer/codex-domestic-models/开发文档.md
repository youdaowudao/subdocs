# Codex 国产模型导入脚本开发文档

状态：开发已实施；隔离测试及独立代码审查记录见本目录，桌面实机验收尚待完成。
日期：2026-10-15。

本脚本面向已经通过 UseGoodAI 使用 GPT 的 Codex 桌面 App，按 DeepSeek 官方方法写入本地模型目录，并保留原有 GPT，让两类模型并列可选。修改目录指向并补齐必要的桌面推理档位，保留默认模型、接口、Key 和其他配置。[参考方法](https://api-docs.deepseek.com/zh-cn/quick_start/agent_integrations/codex/)

## 1. 子项目和交付文件

子项目名称为 `codex-domestic-models`，在 `usegoodai-codex-installer/codex-domestic-models/` 内开发，源码、模型设定和测试都留在本目录。它负责国产模型导入，与上级原有 GPT 一键接入脚本分别维护。交付 `install/codex-models.ps1` 与 `install/codex-models.sh`，分别用于 Windows 和 macOS。

完成后由开发者手动把发布脚本迁移到上级 `usegoodai-codex-installer/install/`，再迁移到 `docs/public/install/`。使用新的脚本文件名，原一键配置入口继续保留；子项目保留完整源码。

## 2. 软件设定中的导入名单

软件内部只维护一份模型名单和元数据，两个平台使用相同数据。名单由维护者写定，用户运行时直接导入。

| 模型 | 请求 ID |
| --- | --- |
| 千问 Max | `qwen3.8-max` |
| 千问 Flash | `qwen3.8-flash` |
| GLM Flash | `glm-5.3-flash` |
| DeepSeek V4.1 Flash | `deepseek-flash` |
| GLM | `glm-5.3` |
| Kimi | `kimi-k3` |
| MiniMax | `minimax-m3` |
| 腾讯混元 | `hy4-preview` |

使用完整、精确的请求 ID，不从产品名称拼接，不使用通配符，不自动转换大小写。DeepSeek V4.1 Flash 的请求 ID 已由官方与本站价格数据核对为 `deepseek-flash`；MiniMax 的小写 ID 尚待核对中转站正式模型配置，不能当作已验证结果。

## 3. 脚本执行流程

1. 读取 App 实际使用的 `config.toml` 和原有有效模型目录；原有目录缺失时，从该 App 取得完整目录。
2. 保留原有 GPT 和其他用户模型，用该 App 的目录补齐缺失条目，再写入软件设定中的国产模型，生成完整目录。
3. 校验目录和配置，备份需要修改的原文件。
4. 写入用户目录中的 `usegoodai-models.json`，更新根级 `model_catalog_json`，并合并必要的桌面推理档位。
5. 成功写入后，复用现有一键安装脚本检测并结束 ChatGPT/Codex 进程，报告关闭结果。
6. 提示用户重新打开 App，新建任务，查看和选择模型。

`usegoodai-models.json` 就是保存全部模型元数据的文件，`model_catalog_json` 只是指向它。Windows 默认放在 `C:\Users\你的用户名\.codex`，macOS 默认放在 `~/.codex`；App 使用自定义配置目录时采用实际目录。

本地目录会替换内置目录，所以必须包含 GPT，不能只写国产模型。[官方目录说明](https://learn.chatgpt.com/docs/enterprise/roll-out-a-gateway)

## 4. GPT 共存和元数据

原有有效目录中的 GPT 和其他用户模型保留完整对象，同 ID 的原有条目优先。没有原有目录时，从目标 App 取得实际目录；App 内置目录用于补齐缺失条目，不覆盖原有对象。不复制另一份独立 CLI 的目录，不硬编码几个 GPT 名字。App 自带后端支持 `debug models --bundled` 时，可用它取得内置目录；具体定位方式由开发者在目标 App 上核实。[官方导出命令](https://learn.chatgpt.com/docs/cli/reference)

用户当前默认模型、复核模型和已有自定义模型都应保留。每个国产模型按官方资料整理完整元数据，至少核对：

- 准确的模型 ID、显示名称、菜单可见性和排序。
- 上下文长度、有效窗口及压缩设置。
- 默认推理档位和可选档位。
- 文本、图片输入能力。
- 补丁工具格式、并行调用及其他能力声明。
- 模型指令和目录格式要求的字段。

不能复制 GPT 模板后只改名字，不能对所有模型启用同一套能力。发布脚本内嵌本版国产模型数据，支持直接远程执行，不要求用户另外下载配置文件或安装依赖。

桌面推理菜单参照 DeepSeek 官方方法配置 `[desktop].enabled-reasoning-efforts`。已有该字段时，以其中档位为基础；没有时，以目标 App 的 GPT 原有可选档位为基础。两种情况都加入本版国产模型所需档位并去重，保留默认推理强度及其他桌面设置，不创建重复的 `[desktop]` 段。每个模型实际可用的档位仍由自己的元数据声明，菜单配置不代表所有模型支持所有档位。

## 5. 保留配置和处理失败

配置只更新根级 `model_catalog_json` 和 `[desktop]` 中必要的 `enabled-reasoning-efforts`，不整份覆盖 `config.toml`，不修改 `auth.json`，不输出 Key。根级字段放在第一个 TOML 配置段之前，桌面字段写入原有桌面段；正确处理已有字段、路径转义和文件编码。

解析或写入失败时保留或恢复原文件，不结束进程，不报告完成。开发和测试只写本子项目内的隔离目录，不修改个人配置，不使用 `rm`。

脚本沿用现有 Responses 接入，中转站负责转换，用户自行切分组。本项目不开发代理、缓存策略、分组管理或模型表现评测。

## 7. 重复运行与 App 升级

重复运行就是更新：本工具管理的国产模型按本版设定整条替换，不保留旧对象中已取消的字段；加入新增项，移除本工具已经取消的条目。首次导入遇到同 ID 的国产条目，也在备份后按本版设定更新。

GPT 和其他用户模型保留完整对象，目标 App 可取得的新条目只补缺。本次不承诺刷新全部原有 GPT 元数据。只记录上次由本工具管理的 `slug` 列表，GPT 不进入这个列表；不增加其他管理系统。

配置和目录与 DeepSeek 官方方法一样放在用户目录中，正常 App 升级后继续读取。升级本身不意味着导入失败，也不要求用户每次升级重跑脚本；文件保留的预期依据是其与 App 安装目录分离。[官方配置位置](https://learn.chatgpt.com/docs/config-file/config-advanced)

不增加自动重跑、后台程序、定时任务或升级 hook。用户主动更新时重新生成目录。固定本地目录不会自动加入未来新增的 GPT，作为该配置方式的限制说明即可，不扩展成本项目的自动同步功能。

再次运行原一键配置脚本会覆盖 `config.toml` 并移除目录指向，此时重新运行导入脚本即可恢复。

## 8. 交付检查

开发者完成以下检查即可：

1. 桌面 App 正确显示 GPT 和确定的 8 个国产条目，选中的条目使用准确请求 ID。
2. 元数据完整，桌面推理档位补齐且原有 GPT 档位保留，选项与输入能力符合设定，默认模型和原配置保留。
3. 重复运行确实更新，模型不重复，用户其他模型不丢失。
4. 失败保留原文件；成功后进程处理与原脚本一致。
5. 做一次正常 App 升级检查，确认原配置和目录继续读取，不把所有未来版本的假设变成复杂兼容系统。
6. 发布脚本与子项目交付版本一致，再由开发者手动迁移发布。

源码、生成的两个发布脚本及隔离测试已在本子项目实现。真实桌面升级尚未执行；此前的详细源码讨论仅作为备查，不增加到开发流程中。
