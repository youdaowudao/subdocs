## 1.1.9：客户可直接复制错误与打开日志

用户明确：故障发生在客户电脑，不方便让客户查看隐藏日志、在 PowerShell 输入一串命令；日志不得写桌面，即使 EXE 下载到桌面。相对 1.1.8，本次只调整错误反馈与日志写入方式，软件渲染和独立缓存设置不变，仍未确认原闪退根因。

- 通过已有终端或重定向的标准错误输出一条简短、脱敏的错误，正常启动静默；不创建新终端。
- 无可用终端时，只在捕获错误后将详情原子写入 `%LOCALAPPDATA%\UseGoodAI\QuickConnect\logs\latest-error.log`；正常诊断在内存中限量保留，正常启动不创建错误日志。仅替换同一路径的上次错误，不跟随 EXE 放置位置，不回退到桌面或未知目录。
- 致命错误使用 Windows 原生 Task Dialog，提供「复制错误信息」「打开日志文件夹」「关闭」；复制内容为简短错误、系统和界面运行库版本，隐藏 Key 和导入链接。日志写入失败时仍保留可复制错误。弹窗不依赖 WebView2。
- 手动备用入口只需 `Win+R` 粘贴 `%LOCALAPPDATA%\UseGoodAI\QuickConnect\logs`；以弹窗按钮为客户主路径，取消要求客户输入 PowerShell 命令。
- 增加正常不落盘、终端优先、错误输出失败回退、固定文件替换、日志写入失败、脱敏和内存上限测试；增加 Windows 原生终端检测、实际弹窗按钮、剪贴板及资源管理器打开目标目录的测试。原生弹窗通过测试专用 EXE 调用与成品相同的函数，不在交付程序增加故障注入开关，不当作客户原故障已复现。
- 无法保证报告系统直接终止、进程进入错误处理前的崩溃或所有 Go 后台协程崩溃；未宣称捕获全部硬崩溃。客户 Win11 x64 双显卡实机、真实接口及完整 Codex 桌面任务仍未验证。
