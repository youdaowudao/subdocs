# 生图 0.9.6 进度汇报发布测试（2026-11-13）

记录版本 1.0.0；生图工具 0.9.6（源码提交 `usegoodai-imagines-tool` 49513a7），快速接入助手 1.1.13。

## 起因

客户 Windows 上的 Codex（gpt-6.1-sol，完全访问）生图时等了约 5 分钟没有任何输出后放弃，后台显示图片早已生成。0.9.5 从发出请求到存图之间什么都不输出，只有 10 分钟总超时，看不出卡在发送、等生成、回传还是保存。

## 改动

- 工具在 stderr 逐段输出 `[生图 分:秒] 内容`：开始、线路、请求已发出、中转站已返回（HTTP 状态、用时、数据大小）、接收进度、接收完成、已保存；同一阶段每 10 秒再报一次。
- 卡住时自己停下：发出后 3 分钟没有开始返回、发送 / 接收 / 下载连续 60 秒没有新数据，结束并写明停在哪一步；错误 JSON 带 `request_sent`。提示里不再提扣费。
- Skill：Code Mode 下用嵌套 `exec_command()`，每收到进度行就 `text(...)` 转发，外层每 30 秒交回一次，Codex 把最新一行原样告诉用户。
- `doctor` 不再在 Windows 全新安装后误报“放行规则内容与当前安装位置不一致”。

## 测试方法

`tests/image-progress-codex.py`，工作流“生图进度汇报验证”（只做验证，不是必需检查）：在 GitHub 托管机器上装官方 Codex 0.167.2 与候选生图工具，本机用测试证书冒充 `api.usegoodai.com`，模型由本地 Responses 接口按 Skill 的 Code Mode 脚本驱动。四种情况：

| 情况 | 模拟 | 期望 |
| --- | --- | --- |
| 正常 | 35 秒后返回约 5.7 MB，1 MB/s | 等待中每 10 秒一行，接收进度，保存成功 |
| 慢速 | 5 秒后返回 2.3 MB，约 60 KB/s | 每 10 秒报接收速度，保存成功 |
| 中断 | 发出 1.0 MB 后不再发送 | 60 秒没有新数据后停下 |
| 不返回 | 一直不回响应头 | 3 分钟后停下 |

不使用真实 Key、Secrets 或真实中转站；真实上游生图、计费和客户网络未验证。

## 结果

### Windows（actions-test ddd8eee，运行 43242005487）

Windows Server 2025（10.0.26100），Codex 只提供 `exec`（Code Mode）。PowerShell 7 与系统自带 Windows PowerShell 5.1（隐藏 PowerShell 7 后 Codex 实际调用 `powershell.exe`）结果相同：

| 情况 | 用时 | 命令结束前模型已收到的进度 | 结果 |
| --- | --- | --- | --- |
| 正常 | 42～44 秒 | 5 行（开始、线路、已发出、已等 9 秒、已等 19 秒） | 保存成功 |
| 慢速 | 约 46 秒 | 6 行（含“接收中 874 KB/2.3 MB，近 10 秒 58 KB/s”） | 保存成功 |
| 中断 | 约 67 秒 | 每 10 秒一行“已 N 秒没有新数据” | `接收中断：60 秒没有新数据，已收 1.0 MB/5.7 MB。`，`request_sent: true` |
| 不返回 | 约 181 秒 | 每 10 秒一行“等待中转站生成，已等 N 秒” | `请求已发出，已等 3 分钟，中转站没有开始返回。`，`request_sent: true` |

- 在 Codex 之外直接运行：进度行实时到达（0.0、0.2、10.0、20.0、30.0、35.2、40.0、41.2 秒），不是结束时一次性输出。
- 全新安装后 `doctor` 的放行规则与 Skill 两项都通过（0.9.5 在同样环境误报不一致）。

### Apple 芯片 Mac

- actions-test 1c773b3（运行 43239343150，旧措辞“1 分 1 秒没有新数据”）：四种情况全部按期望结束。
- actions-test ddd8eee：运行器没有分到 Apple 芯片机器被取消（GitHub 容量问题，不是测试失败）；本次发布候选重跑结果见下。

### 发布候选（actions-test 8a4cd2c）

[生图进度汇报验证 43360024506](https://github.com/youdaowudao/subdocs/actions/runs/43360024506) 三组全部通过，全新安装后 `doctor` 两项通过，Codex 之外直接运行时进度实时到达：

| 情况 | Windows PowerShell 7 | Windows PowerShell 5.1 | Mac（macOS 15.8.2，zsh） |
| --- | --- | --- | --- |
| 正常 | 42.8 秒，结束前 5 行，保存成功 | 44.2 秒，5 行，保存成功 | 47.9 秒，6 行，保存成功 |
| 慢速 | 46.0 秒，6 行，保存成功 | 45.9 秒，6 行，保存成功 | 83.7 秒，10 行，保存成功 |

同一提交的其它检查：工具发布门禁、生图原生升级（四平台）、生图 VPN 系统代理验证（Mac 与 Windows）、Windows 快速接入助手测试、Mac 快速接入助手打包均通过。

### Mac 签名与打开

[Mac 工具签名与打开测试 43360024509](https://github.com/youdaowudao/subdocs/actions/runs/43360024509)：合集 1、2、3 号与 Mac 助手 zip 的 App 签名有效（valid on disk，satisfies its Designated Requirement）；带隔离标记双击提示 “Apple could not verify … is free of malware”（无法验证，可在隐私与安全性中放行），不是“已损坏”。`syspolicy_check` 报 Notary Ticket Missing 与 Internal Xprotect Error，上一版（运行 42972051134）同一运行器上 1、2、3 号同样如此，未签名公证的现状不变。签名只改动 1、2 号启动器并新增 `_CodeSignature`；3 号与上一版已签名合集逐字节一致。签好的 zip 已放回网站下载目录，由下一次推送的同一工作流核对逐字节一致。
