# Windows 助手闪退排查：启动记录（2026-11-11）

记录版本 1.0.0；助手 1.1.12。部分 Windows 11 电脑双击后一闪就退出，多次遇到，根因未确认，不找客户复现。

## 对排查分支 fix-windows-helper-startup-20261111（1.1.8～1.1.10）的分析

- 做法：关闭 WebView2 硬件加速、换新缓存目录；启动日志从 1.1.8 的落盘改为 1.1.9 起只在内存、捕获到错误才写文件；错误用原生对话框。只在 Windows Server 2022/2025 虚拟机上测试。
- 关闭硬件加速没有证据有效：它只影响 WebView2 子进程渲染，显卡问题通常是白屏、黑屏，且 Wails 已为 WebView2 崩溃配置提示框；虚拟机没有真显卡，两种模式表现相同，测试证明不了效果。换缓存针对的 WebView2 初始化失败在 1.1.7 本就弹错误框，与“无提示退出”不符。
- 抓不到原因：日志只能接住 `wails.Run` 错误、主协程 panic 和 Fatal。接不住的正是最可能的情况：Windows 在运行前拦截（智能应用控制、杀毒软件；Server 虚拟机没有这些，测试用的 exe 也没有下载标记）；单实例静默退出（Wails `single_instance.go` 发现已有实例即转交参数并 `os.Exit(0)`，旧实例未完成启动时会忽略）；其它协程或运行时崩溃。1.1.9 改为只在内存记录后，连程序是否启动到 main 都无法判断。也从未查看客户电脑上 Windows 自己的记录。

## 本次做法（只加记录，不改启动行为）

- 每次启动重写 `%LOCALAPPDATA%\UseGoodAI\QuickConnect\logs\启动记录.txt`：启动（版本、系统、进程、是否带导入链接）、创建窗口、窗口已建立、页面就绪、正常关闭；Wails 的错误与标准库日志各一行。
- 启动前查 Wails 单实例的消息窗口：已有实例时记下其进程号和窗口是否可见，并追加记录，保留卡住那个实例的阶段。
- `debug.SetCrashOutput` 把任一协程的 Go 崩溃写入同一文件。不记启动参数（导入链接带 Key）。
- 启动失败的提示框附上记录路径；Windows 使用说明加一行找日志的步骤；助手 README「闪退时看什么」写明各种最后一行的含义与 Windows 自身记录的位置。

## 验证

- Linux 本机：启动记录 4 项单测（阶段行、已有实例追加、无目录不报错、子进程真实崩溃写入记录）与 Go 全量、打包 7 项、文档站 129 项通过。
- Windows：实机冒烟测试在每一步核对启动记录（第一次打开四个阶段、再次打开追加“已有实例 进程 X，窗口可见”、带链接时不含链接与 Key、冷启动重新开始、旧版运行时识别已有实例），结果以 actions-test 上 Windows 快速接入助手测试为准。
- 未验证：出问题的 Win11 实机；记录要等下次再遇到闪退时取回。
