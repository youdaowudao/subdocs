### 同一 PowerShell 会话与配置归因

此前每轮新开 PowerShell，不能计为用户同一窗口中的第二、第三次执行。新增同一原生 PowerShell 5.1 进程八次真实 `irm | iex`；首轮生成的互操作类型在后续调用复用。

1.1.4 的[首轮同会话取证](https://github.com/youdaowudao/subdocs/actions/runs/44694715501)中，联网主界面八次同一 PID 全成功、缓存读取八次、无应用和端口残留，最终真实主界面中文。该组却因配置文件整体哈希不同而验收失败，不能直接当成脚本写配置，也不能忽略。

随后[不运行任何中文化命令的普通启动对照](https://github.com/youdaowudao/subdocs/actions/runs/44696549919)证明：官方应用首次启动会增加自己的 `notify`、插件、市场、MCP、Windows 沙盒和桌面运行字段；普通启动第一、第二次之间，`mcp_servers.node_repl.env.SKY_CUA_NATIVE_PIPE_DIRECTORY` 的运行管道值也会改变。原模型、provider、接口和桌面语言值都保留。验收保留原始文件和逐次哈希，另用 TOML 递归严格比较所有原有配置值，记录应用新增字段；不改官方应用的既有运行配置维护。1.1.5 的[同终端复测](https://github.com/youdaowudao/subdocs/actions/runs/44698686682)仍待核实，不将测试程序的整体绿色或旧失败归因当作结论。

### 桌面网络与重复运行：有效结果通过，主工作区待补

[当前测试](https://github.com/youdaowudao/subdocs/actions/runs/44676654610)。六种网络 × 假 Key 接入首次引导页/未登录页，共 12 组；每组依次在开着、再次运行、关闭时运行，再连续运行 5 次。核对原始附件后，有效结果为首轮 11 组 88 次通过，加上失败组在新机器上的 8 次复测通过，共覆盖 12 组 96 次；不能将其说成所有组都重新运行了一轮。

- 连接拒绝：Windows 防火墙阻断程序外联。
- 连接黑洞：相关域名指向 `192.0.2.1`。
- 持续无响应：域名指向本地 TCP 替身，接受 TLS 连接后 300 秒不回复。
- 解析失败：本地 DNS 返回 NXDOMAIN。
- 解析污染：相关域名指向错误的回环地址。
- 正常联网：运行器原网络。

初轮“完全断网＋未登录页”八次输出成功但缓存未保留，界面仍英文。该失败完整保留在 `windows-round1`。后续[三台独立运行器](https://github.com/youdaowudao/subdocs/actions/runs/44680914615)各运行完整八次，24 次全部通过；每台均核对 1.1.3 的原始哈希、前次缓存和中文文本，并收集数据库日志。原失败根因尚未查明，未凭推测改算法。

2026-11-20 在 [1be8c11 主界面矩阵](https://github.com/youdaowudao/subdocs/actions/runs/44687806349) 的 block-login 再次出现同一失败：八次输出成功、单次约 24 秒、无桌面或端口残留，但重开后无当前缓存、登录页英文。该组不通过，暂停发布。磁盘日志有写入标记，普通重开后日志增加，尚不能据此断言删除原因；增加退出后的原始数据库快照，进一步定位，Mac 草稿已暂存。

新增[首次引导后主界面入口核对](https://github.com/youdaowudao/subdocs/actions/runs/44682465575)：联网引导需选择工程后继续，另有可跳过的引导样式。此前假 Key 组不能计为主工作区验收，后续待补齐。

### 测试中修正的采集问题

- DNS 场景原先选到了没有 IPv4 DNS 配置的虚拟网卡：改为只设置实际 DNS 对象，测试结束恢复。
- 实时读取子进程输出文件撞上文件占用：改为仅读文件长度，子进程退出后再读正文。
- 复用函数时动态脚本块的 `PSScriptRoot` 为空：显式保留测试目录。
- 失败专项检出自动转换换行：检出前关闭 `core.autocrlf`，核对原始字节重跑。

以上均为测试脚本或运行器检出问题，不能计为工具通过，也不能直接当成用户故障原因。失败和中止记录保留在 GitHub 与本地 `.git/local-archive/windows-chinese-20261120/`。
