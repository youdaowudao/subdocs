# 一键接入助手取舍记录

记录重要的取舍：当时的现象、决定、依据和测试编号，方便以后追查。最新的写在最前面。

## 2026-11-08 Windows 生图被“执行策略拦截”

**现象**：Windows 上让 Codex 生图，模型先写一段 PowerShell 脚本（存变量、把描述写进 UTF-8 临时文件、`& $ToolPath generate --prompt-file ...`、再删临时文件），Codex 报“执行策略拦截”。对方反馈生图工具 V0.9.1 也这样。

**实测**：GitHub Actions run 42440004438（测试分支 `image-rules-self-check`）。Codex 0.167.0，Windows Server 2025，PowerShell 7 和 5.1。用本地假模型下发命令，不用真实 Key。V0.9.1 和 V0.9.2 测试版结果完全相同；一键接入新写法（不写权限）和 `sandbox_mode = "workspace-write"` 结果也相同。

| 模型写的命令 | 没有 `[windows]` | 有 `[windows]`（elevated、unelevated） |
|---|---|---|
| Skill 写法（默认位置、中文用户名、带空格用户名） | 离开沙箱，能联网、能写桌面 | 离开沙箱 |
| 前面加 `&`、路径加引号 | 直接拒绝（blocked by policy） | 在沙箱里运行，联不上网 |
| V0.9.0 的临时文件整段脚本 | 直接拒绝 | 直接拒绝 |
| 普通命令（往沙箱外写文件） | 直接拒绝 | 在沙箱里运行，写不进去 |
| 对照：没放行的同名程序 | 直接拒绝 | 留在沙箱里 |

从 V0.9.0 升级到 V0.9.1 或 V0.9.2 后，Skill、全局规则和 `agents/openai.yaml` 都换成新版，没有残留旧写法。

**结论**：

- 生图工具 V0.9.1 本身没问题。被拦的是 V0.9.0 Skill 的 Windows 写法，它在任何设置下都会被 Codex 拒绝。
- V0.9.1 装好后，Skill 里已经没有这种写法。模型还这样写，来源在安装器管不到的地方：继承版本的 Skill 没同步、在旧对话里接着用、Codex 记忆里记着旧做法。
- V0.9.2 的补救：命令被拦后，按正确写法改写再跑一次（正确写法实测一定放行）。它解决不了两件事：用户装的 Skill 不是我们的，以及模型第一次就写错。
- 以前没暴露，是因为旧版一键接入写死了完全访问，命令不进沙箱。现在不写这些预设了，Windows 生图完全靠命令写法命中放行规则。
- 模型第一次能不能写对，需要真实 Key 在 Windows 上生图验证，Actions 里测不了。

## 2026-11-08 一键接入写 config.toml 只改中转站几行

**背景**：旧版整份覆盖 config.toml，并写死 `review_model`、`model_reasoning_effort`、`disable_response_storage`、`approval_policy = "never"`、`sandbox_mode = "danger-full-access"`、`network_access`、`windows_wsl_setup_acknowledged`、`[features]`，还会自己编造 `[windows] sandbox`，并把 Codex App 的权限按钮改成“完全访问”。这些预设会造成沙箱设置错误，而且整份覆盖会冲掉用户的 MCP、插件、项目信任等设置。

**决定**：三处写法完全一致：助手 `connect/codexfiles.go` 的 `ConfigFor`、`install/codex.ps1` 的 `Get-CodexConfig`、`install/codex.sh` 的 `codex_config`。

| 内容 | 处理 | 原因 |
|---|---|---|
| `model_provider`、`model` | 重写，放在第一段 | 中转站必需 |
| `[model_providers.OpenAI]` | 重写，作为第一个段（全文第二段） | 中转站必需；用户的根级设置只能放在它前面，否则 TOML 会把它们算进这个段 |
| `disable_response_storage`、`network_access`、`windows_wsl_setup_acknowledged`、`model_reasoning_effort`、`approval_policy`、`sandbox_mode` | 删除 | 旧版预设，造成沙箱设置错误；权限交给用户在 Codex 里自己选 |
| `review_model` | 删除 | 不写时默认跟当前模型一样 |
| `model_catalog_json`（国产模型列表） | 删除 | 和以前整份覆盖时一样：重新接入后国产模型要再导入，助手会显示“需重新导入” |
| `profile` | 删除 | 它会盖过 `model`，接入不生效 |
| `forced_login_method`、`cli_auth_credentials_store` | 删除 | 审查发现后用户决定删。留着 `forced_login_method = "chatgpt"` 时 Codex 报 Not logged in；留着 `cli_auth_credentials_store = "keyring"` 时 Codex 读系统钥匙串、不读 auth.json。两种情况都是导入显示成功、Key 却不生效（本机 Codex 0.167.0 实测） |
| 所有 `[model_providers.*]`，包括子段、`[model_providers]`、`model_providers.xx = `、`model_providers = {…}` | 删除 | 不按接口名判断，以后改名也能清掉旧接口；用户自己的本地模型接口不保留 |
| `[windows]` | 原样保留，不写也不删 | 由 Codex App 设置沙箱时写入。实测：没有 `[windows]` 时，Codex 会拒绝所有不能放进沙箱的命令，连普通命令也拒绝（见上一节）。旧版自己编造沙箱值的做法去掉 |
| `[features]`（goals、image_generation） | 新用户不写，老用户已有的保留 | 这两项本来就默认开启 |
| 其它（MCP、插件、项目信任、hooks、tui、desktop、notice、注释等） | 原样保留，位置不动 | 不是中转站的内容 |
| Codex App 权限（`.codex-global-state.json`） | 不再修改 | 权限方面只有生图工具自带的放行规则，其它权限都不改 |
| TOML 格式检查 | 不做 | 一键写入只写上面这几行，别的不写；旧文件有备份 |

细节：沿用旧文件的换行（CRLF 或 LF），去掉 UTF-8 BOM，文件末尾不加换行；三处的键名匹配都不区分大小写。“恢复官方”本身没有改。

识别规则（审查后补上，三处相同；“恢复官方”仍用旧规则）：
- 多行字符串逐字符跟踪：注释和单行字符串里的 `"""`、`'''` 不算开头；`"""` 里的 `\"""` 不算结束；结束时最多再带两个引号。
- 表头按 TOML 键名写法识别（裸键、带转义的 `"…"`、`'…'`，用点连接），所以 `[projects."C:\\[work]"]` 这类引号里带 `]` 的项目路径能认出来；多行数组里单独一行的 `[1, 2]` 不会被当成表头。
- 要删的键的值跨多行时（多行字符串、数组、行内表），一直删到值结束；字符串和注释里的括号不算。
- 要删的根级键和 `model_providers` 写成 `"model"`、`'model'` 这种带引号的键名也能认出。
- 去掉首尾空行时，只把空格和 Tab 算空白（TOML 只认这两种）。

**测试**：`connect/importconfig_test.go` 有 14 组样例，覆盖用户真实 config 的结构、CRLF、BOM、多行字符串、注释和字符串里的引号、加点和行内写法、各种段名写法、引号里带 `]` 的段名、带引号的键名、跨多行的数组、注释、1.1.3 写过的旧配置，要求助手、`codex.ps1`、`codex.sh` 输出逐字节一致。PowerShell 版本机用 pwsh 7 跑，`windows-quick-connect` 工作流在 Windows 上用 pwsh 7 和系统自带的 Windows PowerShell 5.1 各跑一遍；`codex.sh` 本机用 mawk 和 busybox awk 跑，macOS 的 BSD awk 由 `mac-quick-connect` 工作流跑同一个测试。

**已知限制**：脚本按行处理，不是完整的 TOML 解析。极少见的写法可能导致写出的文件无效，这时可以从备份恢复。例如多行数组里单独一行、长得和表头一样的 `["a"]`，或键名里写了转义字符。

## 2026-11-08 回退到 15:53 的 1.1.3（发布为 1.1.5）

**现象**：11-05 15:53 之后的几个版本，在 Win11 上窗口闪一下就消失，导入后也会消失。

**决定**：
- 退回 15:53 的 1.1.3 代码。
- 取消 17:18 的 CSS 改动；合入 20:57 修 Mac 安装脚本的改动。
- 内置生图 V0.9.1，生图工具本身没有问题。
- 1.1.4 的版本号已经用过，所以发布为 1.1.5。上一稳定版仍然是 20261105-1538，出过问题的版本不会轮换成上一稳定版。

**根因**：没有确认。Windows Server 2022、2025 上复现不出来；GitHub 的 Win11 测试机停在系统首次登录页面，做不了“窗口是否可见”的检查。

**门禁缺口**：
1. 17:18 的版本上线时，还没有 Windows 自动测试（`windows-quick-connect` 工作流是 19:26 才加的）。
2. Actions 不会拦住 Cloudflare 部署：推到 main 就上线，测试失败也不会阻止发布。
3. 1.1.4 的冒烟测试只检查窗口句柄，而且只在 Windows Server 上跑，没有检查窗口是否真的显示，也没有 Win11。
4. 使用说明里不写版本号，用户反馈时说不清自己用的是哪一版。

现在的冒烟测试 `tools/windows_smoke.ps1` 会检查：窗口可见、不是最小化、持续 10 秒以上；再次打开时，以及打开网站导入链接时，参数交给已经打开的窗口；上一稳定版正在运行时打开新版。它仍然只在 Windows Server 上跑。
